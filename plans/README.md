## Direction — options for the maintainer (not ranked against the bugs)

Grounded in repo evidence; each is a choice, not a defect.

1. **Finish "insert building" into a placement tool (build, M).** The glTF
   half exists (`inserted-building.ts`, `insertedModelUrl`/`insertAt` options)
   but no caller passes a model or a position; the comments in
   `create-app.ts:61` ("the context frame ambition") and `visual-style.ts:82`
   ("hero models" showing through the frosted ghost style) describe an
   architecture-visualisation tool: drop a proposal into the ghosted city and
   check it at a chosen date/time. Minimal path: file picker/drag-drop →
   object URL → existing `GLTFLoader`; click-to-place via the existing
   double-tap terrain raycast; yaw + uniform scale; delete. Trade-off: glTF
   axis/unit conventions are a rabbit hole — show the model's bounding box
   and offer "seat on ground" rather than guessing. Do plan 005 first (it
   makes the inserted object collidable and focusable).
2. **Inspect cursor + undo demolish (build, S–M).** `pickCityObjectId`
   already resolves the aimed object; the tile carries `measuredHeight`,
   `roofType`, `Dachneigung`, `function` (86 % generic in this tile — show
   only populated fields). Undo is a `CityJsonDocument[]` stack plus one
   re-parse because `filterCityObject` never mutates. Trade-off: decoding
   ALKIS codes into labels is the real cost; ship height/roof pitch first.
3. **Scene state in the URL (build, S–M, after PR #16).** Every knob is
   already a handle setter mirrored on `window.__poc`; nothing reads or
   writes the URL. "This corner at 08:00 on 21 December" becomes a link,
   and e2e/visual-review repros become `page.goto(url)`. Encode only the
   stable subset (tile, pose, heading, ISO datetime, style) while PR #16
   churns the look sliders; keep `__poc` for the e2e-only actions.
4. **Neighbour tiles (spike, L; cheap variant S).** Six matching
   CityJSON+DGM pairs are committed (3×2 block of 2 km tiles) but one is
   hard-coded; walking to the tile edge today glides over nothing
   (`fps-movement.ts:90-91`). The offset-based architecture is ready for a
   shared recenter point, but `assertCityOnTerrain`, the minimap bounds,
   `terrain.heightAt` and the whole-scene shadow frustum assume one tile,
   and the loader's `objectid` attribute is `Uint16` (65,535 objects per
   loader instance — load tiles as separate layers). Cheap variant: a
   tile picker (plan 004's `lib/city/tile.ts` makes it a one-constant
   change). Also adjacent: a day-animation play button is one rAF loop over
   the existing `updateSun` (S); a shadow-hours probe over the BVH is a
   spike.

## Findings considered and rejected

- **"Walk-mode collider can lock the player inside a building"** — all
  city materials use three's default `FrontSide`, so the collision ray never
  hits back faces; a player teleported inside a shell walks straight out.
  Not a bug (a cosmetic "nudge out on teleport" is listed as deferred in 005).
- **CI dependency caching / build-cache key** — measured: the whole run is
  2m38s wall, installs take 3–9 s per job, the cache step 8 s; ≈4.5 billable
  minutes per run, dominated by the 2-minute software-GL e2e job. Not worth
  a plan.
- **Drop ESLint (keep Biome only)** — a legitimate option (`eslint-config-next`
  rules have no matching surface: no `next/image`, no `<a>`, one route) but a
  maintainer judgment; recorded here, not planned.
- **CSP / security headers** — no auth, cookies, user content or backend;
  add `frame-ancestors` only when embedding becomes a goal.
- **Verify `skills-lock.json` in CI**, **SHA-pin GitHub Actions**,
  **hooks run repo-controlled `bun fix`** — hygiene for a public repo that
  merges PRs; low value for a solo POC. Noted, not planned.
- **Replace `date-fns` with `Intl`** — `react-day-picker` (used by the
  reachable calendar) depends on it; removing it drops zero packages.
- **Render-on-demand loop** — a walkable viewer with continuous input needs
  continuous frames; rAF already pauses hidden tabs.
- **`docs/architecture.md`** — the frame comments in `lib/city/sun.ts`,
  `ground-clamp.ts`, `recenter.ts` and `create-app.ts` are accurate; the
  README (plan 006) links them instead of duplicating.
- **Pre-push hook, `.env.example`, CONTRIBUTING** — CI gates every PR, one
  optional env var, AGENTS.md covers conventions.
- **`next.config.ts` `/city → /` redirect** — harmless history; leave it.
- **`terrain.mesh.castShadow = false`** — a visual decision (terrain relief
  is 19.7 m over 2 km); left to the maintainer, especially with PR #16 open.
- **Characterisation tests for `create-app.ts` / `city-walk.tsx`** —
  would test WebGL stubs; extract pure pieces instead (partly done by 003/004).
- **Demolish as data-level re-parse, synchronous CityJSON parser, fly mode
  without collision, global three-mesh-bvh prototype patching** — documented
  decisions; not findings.
